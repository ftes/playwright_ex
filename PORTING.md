# Porting guide

How to port upstream code (`microsoft/playwright` at the pinned `Playwright.Driver.version/0`)
so that a version bump stays a matter of porting `git diff vA vB` hunks. The why is in
[`docs/architecture.md`](docs/architecture.md).

## Where things go

| Upstream | Here |
|---|---|
| `packages/playwright-core/src/client/*.ts` | `lib/playwright/client/`, `Playwright.Client.*`, ported by hand; `errors.ts`'s exceptions are `Playwright.{PlaywrightError, TimeoutError, TargetClosedError, AbortError}` |
| `packages/playwright-core/src/outofprocess.ts` | `Playwright.OutOfProcess`, ported by hand |
| `packages/utils/{zones,pipeTransport}.ts` | `Playwright.Runtime.Zones` (`AsyncLocalStorage` as the process dictionary), `Playwright.Transport.Pipe`, ported by hand |
| `packages/isomorphic/` | `lib/playwright/isomorphic/`, `Playwright.Isomorphic.*`, ported by hand (of `cssParser.ts` only its error) |
| `packages/isomorphic/deviceDescriptorsSource.json` | `Playwright.Isomorphic.DeviceDescriptors`, generated by `mix playwright.gen.api` (`Playwright.devices/0`) |
| `packages/playwright/src/matchers/` | `lib/playwright/matchers/`, `Playwright.Matchers.*`, ported by hand; `matcherHint.ts`'s `ExpectError` is `Playwright.ExpectError` |
| `packages/protocol/spec/*.yml` | `Playwright.Protocol.{Validator, Metainfo}` (`protocol/src/validator.ts`, `isomorphic/protocolMetainfo.ts`), generated by `mix playwright.gen.protocol` |
| `docs/src/api/*.md` (`api.json`) | `lib/playwright/api/`, `Playwright.{Browser, ...}`, generated by `mix playwright.gen.api` |
| `packages/protocol/src/serializers.ts`, `validatorPrimitives.ts` | `lib/playwright/protocol/`, ported by hand |
| `tests/page/*.spec.ts`, `tests/library/*.spec.ts` | `test/upstream/{page,library}/`, ported by hand |

| `packages/playwright/src/index.ts` (fixtures, artifacts) | not ported: `Playwright.Test` is native, after the non-JS clients' test plugins, with its own `test` macro for the result ([why](docs/architecture.md#test-runner)) |
| `packages/playwright/src/worker/{testInfo,testTracing}.ts`, `test.step`, `errorContext.ts`, `reporters/{github,json}.ts` | `Playwright.Test.{TestInfo, TestTracing}`, `Playwright.Test.step/3`, `Playwright.Test.{ErrorContext, GitHubFormatter, JSONFormatter}`: what the matchers, traces and failure reports need, ported by hand without `@upstream` (parity covers the client, not the runner) |

## Rules

- One Elixir module per upstream class, named after it (`connection.ts` `class Root` is
  `Playwright.Client.Connection.Root`). Methods keep upstream order and names in snake_case
  (`waitForEvent` is `wait_for_event`, `_wrapApiCall` is `_wrap_api_call`, `isConnected` is
  `is_connected`). Fields keep their JS spelling (`:_mainFrame`).
- Every module states its source: `@upstream "packages/playwright-core/src/client/page.ts"`.
  No line numbers. Its file starts with the upstream file's copyright lines, a "Ported to Elixir
  and modified" line and the license (Apache-2.0, section 4): `mix playwright.notices` writes
  them, the generators write their own, `mix playwright.parity` checks them. A file ported
  without `@upstream` is listed in `@derived` in `Mix.Playwright.Notices`.
- Comment only deviations. `# deviation: <reason>` marks a changed upstream statement,
  `# Elixir only: <reason>` an addition with no upstream counterpart (in a moduledoc:
  `Deviations:`, `Elixir only:`). A skipped statement or method keeps its upstream text with a marker,
  `# this._instrumentation.onApiCallEnd(apiZone);  -- not ported`, optionally `-- not ported: <reason>`.
  A method under another name says so: `# send  -- ported as send_message/2 (Kernel.send/2)`.
  `mix playwright.parity` reads these two: a method named on such a line counts as covered,
  and a module-level marker line counts for the upstream order.
  Prose docs follow the same rule: they describe our code, and name a deviation as one
  ([AGENTS.md](AGENTS.md)).
  Markers are per line. Upstream `TODO:` comments become `Upstream to-do:` (credo fails on TODO).
- Deviate only where the port requires it: the OTP runtime, testInfo only in a `Playwright.Test`
  test (`Playwright.Test.TestInfo`), Elixir's public API.
  Check upstream at the pin before handling an edge case. If its client has the same behaviour,
  keep that, even when it looks wrong, and don't add a special case for it: every deviation is
  carried through each version bump. If it matters, report it upstream and list it under "Upstream
  issues to re-check". Removing a deviation nothing requires is an improvement.
- Every upstream client and matcher file needs a module (`mix playwright.parity` fails
  otherwise). A file left out on purpose (type-only, not in api.json) goes in `@unported_files` in
  `Mix.Tasks.Playwright.Parity`, with a reason.
- Upstream-shaped code has a few credo checks relaxed (`.credo.exs`), so statements stay in
  upstream order. Don't restructure ported code to please a linter.
- Public methods take the JS arguments, options last as a map with JS keys (`launch(this,
  options \\ %{})`). After porting one, `mix playwright.gen.api` adds it to the facade;
  Elixir-only adjustments to the public API go in `Mix.Playwright.ApiRules`.

## Idioms

| JS | Elixir |
|---|---|
| ChannelOwner instance | `%Playwright.Page{guid, conn, table, type, initializer}` handle (a public class's struct is its facade's: `use ChannelOwner, struct: Playwright.Page`, or `__struct_fields__/0` for a plain struct); fields are rows of the connection's table (`Playwright.Runtime.Conn`) |
| `new X()` for a runtime class (EventEmitter, TimeoutSettings, Waiter) | `X.new(..., owner)` via `Heap.new_object(__MODULE__, owner)`: rows on the owning protocol object; without an owner, process-local (only its creator may use it) |
| `this._x` / `this._x = v` | `get(this, :_x)` / `put(this, :_x, v)` (`Playwright.Runtime.Heap`) |
| `Set` / `Map` fields | `set_add/3`, `set_has/3` / `map_get/3`, `map_set/4`, `map_values/2` |
| class without mutable state (Locator) | plain struct with JS field names (`locator._selector`) |
| `class X extends ChannelOwner`, `super(...)` | `use Playwright.Client.ChannelOwner`, `ChannelOwner.new(__MODULE__, parent, type, guid, init)` |
| `super.foo()` | `Parent.foo(this)` |
| `this.foo()` where a subclass may override | `impl(this).foo(this)` (`Heap.impl/1`: the client module of a facade struct) |
| `@apiCall({ title: 'X' })` / `@apiCall()` / `@internal` method decorator | `@api_call %{title: "X"}` / `@api_call %{}` / `@internal true` above the def (`Playwright.Client.Decorators`): the whole body, JS default parameters included (applied in the body), runs through the receiver's `_wrap_api_call/3` |
| `this._channel.foo(params, options)` | `channel_call(this, :foo, params, options)`; the generated validator converts to the wire |
| `this._channel.on('event', ...)` | `EventEmitter.on(_channel(this), "event", ...)` |
| `X.from(channel)` | identity: channels and owners are the same handle |
| `X.fromNullable(channel)` | `X.from_nullable(channel)`: `nil` when absent (`X \| null` results are `nil`) |
| `await p` | `Promise.await(p)` (an await point: a listener's or async function's caller continues) |
| async function called without `await` | `Promise.async(fn -> ... end)` (local), `owner: obj` / `shared: true` for a latch; `Promise.void/1` when nothing awaits it |
| `new Promise(executor)`, `.then`, `.catch`, `Promise.race/all/any` | `Promise.new/0,1` (local) or `Promise.new(owner[, executor])` (latch), `then_/2`, `catch_/2`, `race/1`, `all/1`, `any/1` |
| `Date.now()` | `System.os_time(:millisecond)`: OS time, which the browser reads (`System.system_time/1` can lag it under the VM's time correction) |
| `setTimeout` / `clearTimeout` | `Promise.timer/1` (+ `Promise.free/1`), or `Promise.void/1` around a sleep |
| `currentZone().data(...)`, `.with(...).run(...)` | `Zones.data/1`, `Zones.with/3` |
| `throw` / `try {} catch` / `instanceof` | `raise` / `rescue` / struct match (`Errors.is_playwright_error/1`); `new Error(msg)` is `raise msg` (`RuntimeError`) |
| `e.message = ...` | `e = Errors.rewrite_error_message(e, ...)` (exceptions are immutable) |
| `undefined` / `null` | `nil` / `:null` |
| default parameter, omitted (`undefined`) optional argument | the facade passes `nil` for omitted optional positional args: apply the default in the body (`x = if x == nil, do: default, else: x`); JS `null` is `:null` |
| `let x` reassigned inside a closure | a heap field, or restructure the closure to return the value |

## Shims (OTP runtime)

JS runs the client on one thread; here it runs in the callers' processes, and the connection
process alone writes state and dispatches one message at a time
([why](docs/architecture.md#runtime)). These shims stand in where ported code relies on the
single thread. Use each only where the JS code needs it, with its marker.

- **Promise kinds** ([why](docs/architecture.md#runtime)). A local promise (`Promise.new/0,1`,
  `timer/1`) is awaited once, by its creator (a second await hangs). A promise awaited more than
  once, by another process, or stored in a field is a latch on its owner,
  `Promise.new(owner[, executor])`, with a comment naming the reason and no deviation marker:
  `# A latch on the browser.` (`Client.Browser.new/4`), `# A latch: `stop` awaits it from another
  process.` (`Client.RouteHandler._handle_impl/2`). An async function called without `await` is
  `Promise.async(fun)`: local, or a latch with `owner: obj` (kept in a field,
  `Client.Page.pause/2`) or `shared: true` (owned by the calling process until it exits,
  `Runtime.Facade.promise/3`). `Promise.void(fun)` when nothing awaits it
  (`Client.BrowserContext.new/4`, dialog auto-dismiss).
- **`atomic`/`update`** ([why](docs/architecture.md#runtime)). A read-modify-write that JS does
  synchronously, but that spans other processes here, is `Heap.update/3` or `Heap.atomic/2`; the
  fun runs in the connection and must not await (compute first, then update). Comment it as one
  synchronous section (`Client.Selectors.set_test_id_attribute/2`).
- **`on_sync`** ([why](docs/architecture.md#ordering)). A client listener that only updates
  state runs inline in the connection: `# Elixir only: on_sync, a pure state update.` above
  `EventEmitter.on_sync/3` (`Client.Page.new/4`, `frameAttached`). It must not await or call
  the driver.
- **`on_reply`** ([why](docs/architecture.md#ordering)). JS runs the statements after an `await`
  before it dispatches the next message; here the caller runs them later. When an event the call
  enables reads what they write (`this._bindings.set(...)` before a `bindingCall`), move them
  unchanged into `channel_call/5`'s `on_reply` fun, which runs in the connection on reply (pure
  state, no await): `Client.Page.expose_function/3`.
- **Subscribe-first** ([why](docs/architecture.md#ordering)). Check-then-subscribe (`if (!cond)
  await waitForEvent(...)`) is one tick in JS; here dispatch may run in between. Subscribe
  before the check, or make the check part of the subscription, and mark it
  `# deviation: subscribe-first (OTP runtime)` (`Client.Frame._wait_for_navigation/3`). The same
  applies to test ports.

- **`$callers`** ([why](docs/architecture.md#runtime)). Any user function the client stores and
  calls later from another process (a handler, a URL matcher, a predicate, `onFrame`) runs on the
  registrant's behalf: capture `Callers.capture()` where it is registered (in the caller, not in
  an `on_reply` fun) and `Callers.adopt/1` or `run_as/2` before each call, marked `# deviation:`
  (`Client.RouteHandler`, `Client.Page.add_locator_handler/4`). `mix playwright.parity` lists
  api.json's function-typed parameters and fails on one missing from its `@function_params`.

## Traps

- A listener runs in a process of its own while the connection waits for it to return or first
  await. Blocking on non-Playwright work there stalls dispatch, as it would in JS.
- A closed context (and what it owned) stays readable while its connection retains it: the recently
  closed ones, up to a row cap per connection that concurrent users share. What one dispose frees
  (a context with its pages, or a browser) stays readable at least until a later dispose on the
  connection trims it, even one of a close running at the same time (the close still returns); a
  launched browser's close disposes its contexts one by one, the oldest trimmed first, so all stay
  readable unless they and concurrent closes on the connection exceed the cap (a connected
  browser's close takes no disposes: its objects stay until its connection stops). Older ones, and
  those of a connection that is gone, raise TargetClosedError, except the closed-state getters
  (`Page.is_closed`, `BrowserContext.is_closed`, `Browser.is_connected`)
  ([why](docs/architecture.md#object-lifetimes)). Read what a test needs right after the close;
  library code that reads a closed object much later (upstream's runner reads videos at the test's
  end) reads it while it is open, as the recorder does.
- `then_`/`catch_` are lazy: a reaction nobody awaits never runs. For a side effect use
  `Promise.void(fn -> f.(Promise.await(p)) end)` (`p` a latch).
- Public entry points run inside `Playwright.Runtime.Facade.call/2` (the generated facade does
  this for async methods): it names the call for error messages; it does not block dispatch.

## Tests

- North star: run what the non-JS clients (Python, Java, .NET) run
  ([why](docs/architecture.md#mirroring-upstream-specs)). Specs of JS-only API (api.json `only:
  ["js"]`, e.g. `launchServer`), of the in-process server (`toImpl`, `__testHook*`, heap counts)
  or of the test runner are not ported; port what exercises the client. Benchmark:
  playwright-python `tests/upstream_not_ported.txt` and playwright-java
  `playwright/src/test/upstream_not_ported.txt`; a spec they run (e.g. via the driver's
  `launch-server` CLI) we run too.
- Mirror upstream spec files: one module per file, `@upstream "tests/page/page-goto.spec.ts"`
  then `use Playwright.UpstreamCase` (which tags the module with it: `mix test --only
  upstream:tests/page/page-goto.spec.ts`). Tests keep upstream's names and order; a name starts
  with the test's ID in `test/upstream_registry.md` (upstream's `tests/registry.md` at the pin):
  `test "PA-001 should fire load when expected"`. ExUnit has no nested describes: `describe "a
  b"` for upstream's `describe('a') > describe('b')`. Helper modules of a spec (event
  subclasses) are top-level modules: parity treats nested modules as specs. A spec with no test
  module (driver internals, Node-only tooling) has all its tests ruled out (Skips).
- `mix playwright.parity` checks the mirrors against the specs and the registry, and the skips
  below: its moduledoc says what fails.
- Browsers come from `Playwright.Test.BrowserPool.browser/1` in `setup_all` (upstream's worker);
  a spec that needs other launch options launches its own, as upstream's do.
  `Playwright.DriverCleanup` closes the browsers a test or module created and the module's
  contexts; `Playwright.Test` closes a test's leftover contexts.
- Fixtures mirror upstream's (`server`, `https_server`, `browser_type`, `browser`, `asset`, ...),
  see `Playwright.UpstreamCase`. `Playwright.TestServer` ports `tests/config/testserver`;
  assets and certs come from `Playwright.Upstream` (the pinned release, not vendored).
- Contexts and launches get Playwright Test's defaults (`locale: "en-US"`, `artifactsDir`, ...)
  from `Playwright.UpstreamCase.setup_playwright/2`; a test that drops one passes it as upstream
  does (`launch(browser_type, artifacts_dir: nil)` for `{ artifactsDir: undefined }`). A driver
  of the test's own: `start_playwright/2`.
- Headed: `HEADED=1` is upstream's `--headed`. Tag every test that launches headed (or that
  upstream skips when headless) `@tag :headed`: CI runs `HEADED=1 mix test --only headed` (Linux:
  on Xvfb); macOS excludes them, as windows steal focus (`--include headed`). Other `!headless`
  annotations stay comments, as we run headless.
- Tests call the facade (`BrowserType.launch(browser_type, executable_path: path)`), with
  `{:error, e} = ...` for `.catch(e => e)` and the bang form otherwise. Options get snake_case
  keys, nested objects stay as upstream writes them, as maps with the JS keys
  (`new_context(browser, viewport: %{width: 456, height: 789}, record_video: %{dir: dir})`).
- Keep assertions verbatim (we announce `sdkLanguage: "javascript"`, as upstream). Options
  passed `as any` are rejected by the facade: assert that, with a comment. Any other test-side
  change of behaviour is marked like lib code (`# deviation: <reason>`).
- Calls not awaited are `Runtime.Promise.async/1` and `void/1` as in lib code (Idioms), not a
  `Task`, which may send the call late; `shared: true` where upstream checks whether it is done
  (`settled?/1`). `Promise.all` of awaited calls stays `Task.async` + `Task.await_many(_,
  :infinity)`, a `setTimeout` `Task.start` + sleep.
- Assertions in listeners become `send/2` to the test process and `assert_receive` (10 s
  default, `test_helper.exs`); listener state that JS keeps in an array is an `Agent`.
- JS truthiness (`expect(x).toBeTruthy()`) is `Utils.assert_truthy/1`/`assert_falsy/1`, not a
  bare `assert` (`:null` is truthy in Elixir). `expect.poll(fn).toBe(x)` and `toPass` are
  `Expect.poll!(fn, &assert(&1 == x))` and `Expect.to_pass!/2`. A `toPass` callback that assigns an
  outer `let` returns the value instead, as `to_pass!` returns the passing attempt's (a closure
  can't rebind): `box = Expect.to_pass!(fn -> ...; box end)`.
- Local file access: `path.resolve` is `Path.expand/1`, `fs` calls are `File.*!` (raising
  `File.Error`). Don't imitate system or Node error texts: assert the Elixir error and mark it
  `# deviation: Elixir's File error, not Node's text.` Errors the driver sends stay verbatim.
- CI-only failure or flake under load? Reproduce in the Linux container: `scripts/linux/README.md`.

### Skips

A test we don't port stays, bodiless, in upstream order. Every skip reason, on it or on a ported
test, starts with a prefix, then says why:

| Prefix | Meaning | Where |
|---|---|---|
| `not ported:` | out of scope (North star) or missing here | a rule in `test/upstream_not_ported.txt` (format in its header), which `Playwright.UpstreamCase` applies at compile time over the test's own tags; a conditional one (one browser, one loop variant) as `@tag skip: if(..., do: "not ported: ...")` |
| `upstream skip:`, `upstream fixme:`, `upstream fail:` | upstream's `skip`, `fixme` or `fail` annotation | a tag under upstream's condition, on the ported body; unconditional (bodiless) only when the condition holds in every run here (headless, out-of-process driver) |
| `env:` | host or browser behaviour, confirmed with upstream's Node client | a tag |
| `ci:` | fails on CI only | a tag |
| `flaky:` | fails intermittently | a tag |
| `headed:` | a headed test with no display to run on | a tag |

- Tags keep upstream's conditions: `it.skip(browserName === 'webkit')` is `@tag skip:
  if(@browser_name == "webkit", do: "upstream skip: ...")`. `@browser_name` and
  `@browser_major_version` are compile-time attributes of `Playwright.UpstreamCase` (ExUnit has
  no runtime skip), so version and OS gates are tags too, never an `if` around the body, which
  would pass silently.
- `it.fail(cond)` wraps the whole body in `expected_failure(cond, fn -> ... end)`: where `cond`
  holds the test passes only if the body fails, as Playwright Test fails an unexpected pass;
  elsewhere the body runs as is. No `refute` of the last assertion.
- `test.slow()` is `@tag timeout: @slow_timeout`.
- A `not ported:` reason that only lists API names (`not ported: Page.emulateMedia`) is stale
  once one of them is ported: port the test then. If the test still needs something missing,
  say so in words (`not ported: Page.removeAllListeners behavior option`).
- `PW_UNSKIP=env,flaky` runs the tests those prefixes skip (bump step 6).

## Bumping the pinned version

`.github/workflows/upstream-update.yml` checks npm daily and opens a draft PR doing these steps
(`.github/prompts/upstream-update.md`); finish its checklist by hand. Until you comment on or push
to that PR, the workflow also pushes fixes for its CI failures. The mix tasks below live in
`dev/`, which only the dev and test envs compile, so they stay out of the Hex package.

1. `mix playwright.checksums <driver> <node>` (Node bumped only if Python's `NODE_VERSION`
   was): writes the repo-root `DRIVER_VERSION` and `NODE_VERSION` and the checksums.
2. `mix playwright.gen.protocol` and `mix playwright.gen.api`, commit the generated diff.
3. `git diff vA vB -- packages/playwright-core/src/client packages/playwright/src/matchers tests/page tests/library`
   in upstream; port the hunks.
   - Read the runner's diff as well, from this repo:
     `git -C <upstream> diff vA vB -- $(mix playwright.runner_sources)` (the files
     `Playwright.Test` derives from or follows, `@derived` and `@watched` in
     `Mix.Playwright.Notices`). `Playwright.Test` is watched, not parity-tracked.
   - Port the hunks that touch what it ports: testInfo's snapshot paths, errors and steps,
     `test.trace`, `test.step`, error-context, the GitHub reporter and the artifact recording.
   - List new options, fixtures and defaults as features to adopt or skip.
4. `mix playwright.parity` until clean, then `mix test`. New upstream client, matcher or spec files
   show up as missing, removed or since-ported ones as stale exclusions: port or mirror them, or
   update `@unported_files` / `test/upstream_not_ported.txt`. A new function-typed
   parameter shows up too: classify it in `@function_params` (`$callers` under Shims). So does a
   runner file `Playwright.Test` newly cites, or one gone upstream: update `@watched`.
   `mix playwright.notices` gives new files their copyright headers (parity fails on a missing
   or stale one); an MIT source's copyright goes in `NOTICE` too. Copy upstream's
   `tests/registry.md` to `test/upstream_registry.md`. Parity sees new, renamed and removed
   tests (a test named at runtime, in a loop, by its identifier only), not changed bodies: port
   those from the spec diff.
5. Skim `git diff vA vB -- 'docs/src/*.md' ':!docs/src/api'` (upstream's guides) for new patterns
   or caveats the guides in `guides/` should mention. Nothing checks their prose against upstream;
   their snippets are tests in `test/guides`.
   - Check that upstream's locator priority still matches the one-line order in
     `usage-rules.md` ("Locators and assertions"): `locators.md` "Quick Guide" and "Locating
     elements", and `best-practices-js.md` "Prefer user-facing attributes to XPath or CSS
     selectors".
6. Re-check skips that may be gone: run the spec files with `env:` or `flaky:` skips
   (`grep -rlE '"(env|flaky):' test/upstream`) with `PW_UNSKIP=env,flaky mix test <files>` on the
   browser they name (ExUnit runs no skipped test, `--include skip` neither), drop each skip that
   passes, and re-check "Upstream issues to re-check" below.
7. The release then takes the version (upstream's major.minor, our patch; docs/architecture.md
   "Port and versions"): an upstream minor gives X.Y.0, a driver patch bump our patch + 1, as
   does a release of only our fixes. Its CHANGELOG entry names the exact driver.

### Upstream issues to re-check

Problems upstream's own client has too; re-check on each bump, drop what's fixed.

- **macOS WebKit `env:` skips** (9 tests, macOS 26: the proxy for localhost, 127.0.0.1 and
  link-local targets, `colorScheme: null` on a dark host): upstream's client fails them too;
  Linux CI passes.
- **Chromium worker hang** (`workers_test`, tagged flaky): upstream's client hangs too (6/510
  under 2-CPU load). A Chromium bug, reproduced with a bare CDP client: microsoft/playwright#43922
  was closed as https://issues.chromium.org/issues/582409894. Re-check when that is fixed.
- **HTTPS proxy closing mid-handshake**: a FIN during the TLS handshake crashes the driver with an
  unhandled `TLSSocket` error (bundled `https-proxy-agent`), so tests avoid it. Reported as
  microsoft/playwright#43996, GH #130.
- **Firefox file chooser race** (FC-020, skipped on Firefox): Juggler's `FilePickerOverride`
  (Firefox 1572) decides interception when the parent process creates the picker, after
  `Page.fileChooserOpened`. A waiter that unsubscribes on arrival can disable it first, so a native
  picker opens and the input's next click opens none. Upstream's client fails it too (2/20 on a
  just-launched Firefox), GH #149, reported as microsoft/playwright#44143.
- **WebKit empty body after a cut-off request** (NE-143, skipped on WebKit): after
  `loadingFailed(cancelled)`, WebKit usually answers `Network.getResponseBody` with "Missing content
  of resource", which the server turns into the "navigated away" error, but sometimes with
  `{"body": ""}`, so `text()` resolves `""`. Upstream's client does too (1/910 alone, 2/708 under
  load). microsoft/playwright#43508's fix covers Chromium only. GH #245.
- **`toMatchAriaSnapshot` with `.not` and a missing file**: with `updateSnapshots` `none`, `all` or
  `changed` the matcher compares an empty template, which never matches, so it passes.
  `toHaveScreenshot` rejects this case with `handleMissingNegated`.
