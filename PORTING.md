# Porting guide

How to port upstream code (`microsoft/playwright` at the pinned `PlaywrightEx.Driver.version/0`)
so that a version bump stays a matter of porting `git diff vA vB` hunks. See `PLAN.md` for the why.

## Where things go

| Upstream | Here |
|---|---|
| `packages/playwright-core/src/client/*.ts` | `lib/playwright_ex/client/`, `PlaywrightEx.Client.*`, ported by hand |
| `packages/protocol/spec/*.yml` | `PlaywrightEx.Protocol.{Validator, Metainfo}`, generated by `mix playwright_ex.gen.protocol` |
| `docs/src/api/*.md` (`api.json`) | `lib/playwright_ex/api/`, `PlaywrightEx.{Browser, ...}`, generated by `mix playwright_ex.gen.api` |
| `packages/protocol/src/serializers.ts`, `validatorPrimitives.ts` | `lib/playwright_ex/protocol/`, ported by hand |
| `tests/page/*.spec.ts`, `tests/library/*.spec.ts` | `test/upstream/{page,library}/`, ported by hand |
| Node's event loop, `AsyncLocalStorage` | `PlaywrightEx.Runtime.*` (Elixir only) |

## Rules

- One Elixir module per upstream class, named after it (`connection.ts` `class Root` is
  `PlaywrightEx.Client.Connection.Root`). Methods keep upstream order and names in snake_case
  (`waitForEvent` is `wait_for_event`, `_wrapApiCall` is `_wrap_api_call`, `isConnected` is
  `is_connected`). Fields keep their JS spelling (`:_mainFrame`).
- Every module states its source: `@upstream "packages/playwright-core/src/client/page.ts"`.
  No line numbers.
- Comment only deviations. A skipped statement or method keeps its upstream text with a marker,
  `# this._instrumentation.onApiCallEnd(apiZone);  -- not ported`, optionally `-- not ported: <reason>`.
  A method under another name says so: `# send  -- ported as send_message/2 (Kernel.send/2)`.
  `mix playwright_ex.parity` reads both markers: a method named on such a line counts as covered.
  Markers are per line.
- Upstream-shaped code has a few credo checks relaxed (`.credo.exs`), so statements stay in
  upstream order. Don't restructure ported code to please a linter.
- Public methods take the JS arguments, options last as a map with JS keys (`launch(this,
  options \\ %{})`). After porting one, `mix playwright_ex.gen.api` adds it to the facade;
  Elixir-only adjustments to the public API go in `Mix.PlaywrightEx.ApiRules`.

## Idioms

| JS | Elixir |
|---|---|
| ChannelOwner instance | `%Page{guid, loop, heap}` handle; fields live in the connection's ETS heap |
| `new X()` for a runtime class (EventEmitter, TimeoutSettings, Waiter) | `X.new(...)` via `Heap.new_object(__MODULE__)`: in the loop's heap |
| `this._x` / `this._x = v` | `get(this, :_x)` / `put(this, :_x, v)` (`PlaywrightEx.Runtime.Heap`) |
| `Set` / `Map` fields | `set_add/3`, `set_has/3` / `map_get/3`, `map_set/4`, `map_values/2` |
| class without mutable state (Locator) | plain struct with JS field names (`locator._selector`) |
| `class X extends ChannelOwner`, `super(...)` | `use PlaywrightEx.Client.ChannelOwner`, `ChannelOwner.new(__MODULE__, parent, type, guid, init)` |
| `super.foo()` | `Parent.foo(this)` |
| `this.foo()` where a subclass may override | `this.__struct__.foo(this)` |
| `this._channel.foo(params, options)` | `channel_call(this, :foo, params, options)`; the generated validator converts to the wire |
| `this._channel.on('event', ...)` | `EventEmitter.on(_channel(this), "event", ...)` |
| `X.from(channel)` | identity: channels and owners are the same handle |
| `X.fromNullable(channel)` | `X.from_nullable(channel)`: `nil` when absent (`X \| null` results are `nil`) |
| `await p` | `Promise.await(p)` (releases the baton while pending) |
| async function called without `await` | `Promise.async(fn -> ... end)` |
| `new Promise(executor)`, `.then`, `.catch`, `Promise.race/all` | `Promise.new/0,1`, `then_/2`, `catch_/2`, `race/1`, `all/1` (the loop is implicit, as in JS) |
| `setTimeout` / `clearTimeout` | `EventLoop.set_timeout/2` / `EventLoop.clear_timeout/1` |
| `currentZone().data(...)`, `.with(...).run(...)` | `Zones.data/1`, `Zones.with/3` |
| `throw` / `try {} catch` / `instanceof` | `raise` / `rescue` / struct match (`Errors.is_playwright_error/1`); `new Error(msg)` is `raise msg` (`RuntimeError`) |
| `e.message = ...` | `e = Errors.rewrite_error_message(e, ...)` (exceptions are immutable) |
| `undefined` / `null` | `nil` / `:null` |
| `let x` reassigned inside a closure | a heap field, or restructure the closure to return the value |

## Traps

- `Heap.update/3`: the function must not await (compute first, then update).
- Listener and handler code runs handed off under the baton (`EventLoop.spawn_handoff/1`).
  Blocking on non-Playwright work there stalls the driver, as it would in JS.
- Public entry points run inside `PlaywrightEx.Runtime.Api.call/3` (the generated facade does
  this for async methods). It holds the baton for the whole call and names the call for error
  messages. Sync methods are called without it: a sync method that starts promises takes the
  baton itself (`EventLoop.with_baton(this.loop, ...)`, as in `ChannelOwner._update_subscription`).

## Tests

- Mirror upstream spec files: one module per file, `@upstream "tests/page/page-goto.spec.ts"`
  then `use PlaywrightEx.UpstreamCase` (which tags the module with it: `mix test --only
  upstream:tests/page/page-goto.spec.ts`), test names identical to upstream.
- Keep the upstream order. A test that is not ported stays as a bodiless test with a reason:
  `@tag skip: "not ported: Page"` followed by `test "should work"`.
  `mix playwright_ex.parity` compares the names.
- Fixtures mirror upstream's (`server`, `https_server`, `browser_type`, `browser`, `asset`, ...),
  see `PlaywrightEx.UpstreamCase`. `PlaywrightEx.TestServer` ports `tests/config/testserver`;
  assets and certs come from `PlaywrightEx.Upstream` (the pinned release, not vendored).
- Tests call the facade (`BrowserType.launch(browser_type, executable_path: path)`), with
  `{:error, e} = ...` for `.catch(e => e)` and the bang form otherwise.
- Keep assertions verbatim (we announce `sdkLanguage: "javascript"`, as upstream). Options
  passed `as any` are rejected by the facade: assert that, with a comment.

## Bumping the pinned version

1. Bump `@driver_version` (and Node if Python did) in `PlaywrightEx.Driver`, run
   `mix playwright_ex.checksums`.
2. `mix playwright_ex.gen.protocol` and `mix playwright_ex.gen.api`, commit the generated diff.
3. `git diff vA vB -- packages/playwright-core/src/client tests/page tests/library` in upstream; port the hunks.
4. `mix playwright_ex.parity` until clean, then `mix test`.
