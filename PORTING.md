# Porting guide

How to port upstream code (`microsoft/playwright` at the pinned `PlaywrightEx.Driver.version/0`)
so that a version bump stays a matter of porting `git diff vA vB` hunks. See `PLAN.md` for the why.

## Where things go

| Upstream | Here |
|---|---|
| `packages/playwright-core/src/client/*.ts` | `lib/playwright_ex/client/`, `PlaywrightEx.Client.*`, ported by hand |
| `packages/protocol/spec/*.yml` | `PlaywrightEx.Protocol.{Validator, Metainfo}`, generated by `mix playwright_ex.gen.protocol` |
| `docs/src/api/*.md` (`api.json`) | `lib/playwright_ex/api/`, `PlaywrightEx.{Browser, ...}`, generated by `mix playwright_ex.gen.api` |
| `packages/protocol/src/serializers.ts`, `validatorPrimitives.ts` | `lib/playwright_ex/protocol/`, ported by hand |
| `tests/page/*.spec.ts`, `tests/library/*.spec.ts` | `test/upstream/{page,library}/`, ported by hand |
| Node's event loop, `AsyncLocalStorage` | `PlaywrightEx.Runtime.*` (Elixir only) |

## Rules

- One Elixir module per upstream class, named after it (`connection.ts` `class Root` is
  `PlaywrightEx.Client.Connection.Root`). Methods keep upstream order and names in snake_case
  (`waitForEvent` is `wait_for_event`, `_wrapApiCall` is `_wrap_api_call`, `isConnected` is
  `is_connected`). Fields keep their JS spelling (`:_mainFrame`).
- Every module states its source: `@upstream "packages/playwright-core/src/client/page.ts"`.
  No line numbers.
- Comment only deviations. A skipped statement or method keeps its upstream text with a marker,
  `# this._instrumentation.onApiCallEnd(apiZone);  -- not ported`, optionally `-- not ported: <reason>`.
  A method under another name says so: `# send  -- ported as send_message/2 (Kernel.send/2)`.
  `mix playwright_ex.parity` reads both markers: a method named on such a line counts as covered,
  and a module-level marker line counts for the upstream order.
  Markers are per line.
- Every upstream client file needs a module (`mix playwright_ex.parity` fails otherwise). A
  file left out on purpose (type-only, not in api.json) goes in `@unported_client_files` in
  `Mix.Tasks.PlaywrightEx.Parity`, with a reason.
- Upstream-shaped code has a few credo checks relaxed (`.credo.exs`), so statements stay in
  upstream order. Don't restructure ported code to please a linter.
- Public methods take the JS arguments, options last as a map with JS keys (`launch(this,
  options \\ %{})`). After porting one, `mix playwright_ex.gen.api` adds it to the facade;
  Elixir-only adjustments to the public API go in `Mix.PlaywrightEx.ApiRules`.

## Idioms

| JS | Elixir |
|---|---|
| ChannelOwner instance | `%PlaywrightEx.Page{guid, conn, table, type, initializer}` handle (a public class's struct is its facade's: `use ChannelOwner, struct: PlaywrightEx.Page`, or `__struct_fields__/0` for a plain struct); fields are rows of the connection's table (`PlaywrightEx.Runtime.Conn`) |
| `new X()` for a runtime class (EventEmitter, TimeoutSettings, Waiter) | `X.new(..., owner)` via `Heap.new_object(__MODULE__, owner)`: rows on the owning protocol object; without an owner, process-local (only its creator may use it) |
| `this._x` / `this._x = v` | `get(this, :_x)` / `put(this, :_x, v)` (`PlaywrightEx.Runtime.Heap`) |
| `Set` / `Map` fields | `set_add/3`, `set_has/3` / `map_get/3`, `map_set/4`, `map_values/2` |
| class without mutable state (Locator) | plain struct with JS field names (`locator._selector`) |
| `class X extends ChannelOwner`, `super(...)` | `use PlaywrightEx.Client.ChannelOwner`, `ChannelOwner.new(__MODULE__, parent, type, guid, init)` |
| `super.foo()` | `Parent.foo(this)` |
| `this.foo()` where a subclass may override | `impl(this).foo(this)` (`Heap.impl/1`: the client module of a facade struct) |
| `this._channel.foo(params, options)` | `channel_call(this, :foo, params, options)`; the generated validator converts to the wire |
| `this._channel.on('event', ...)` | `EventEmitter.on(_channel(this), "event", ...)` |
| `X.from(channel)` | identity: channels and owners are the same handle |
| `X.fromNullable(channel)` | `X.from_nullable(channel)`: `nil` when absent (`X \| null` results are `nil`) |
| `await p` | `Promise.await(p)` (an await point: a listener's or async function's caller continues) |
| async function called without `await` | `Promise.async(fn -> ... end)` (local), `owner: obj` / `shared: true` for a latch; `Promise.void/1` when nothing awaits it |
| `new Promise(executor)`, `.then`, `.catch`, `Promise.race/all` | `Promise.new/0,1` (local) or `Promise.new(owner[, executor])` (latch), `then_/2`, `catch_/2`, `race/1`, `all/1` |
| `setTimeout` / `clearTimeout` | `Promise.timer/1` (+ `Promise.free/1`), or `Promise.void/1` around a sleep |
| `currentZone().data(...)`, `.with(...).run(...)` | `Zones.data/1`, `Zones.with/3` |
| `throw` / `try {} catch` / `instanceof` | `raise` / `rescue` / struct match (`Errors.is_playwright_error/1`); `new Error(msg)` is `raise msg` (`RuntimeError`) |
| `e.message = ...` | `e = Errors.rewrite_error_message(e, ...)` (exceptions are immutable) |
| `undefined` / `null` | `nil` / `:null` |
| default parameter, omitted (`undefined`) optional argument | the facade passes `nil` for omitted optional positional args: apply the default in the body (`x = if x == nil, do: default, else: x`); JS `null` is `:null` |
| `let x` reassigned inside a closure | a heap field, or restructure the closure to return the value |

## Traps

- `Heap.update/3`, `Heap.atomic/2`: the function must not await (compute first, then update).
- **A promise awaited more than once, by another process, or stored in a field must be a latch**
  (`Promise.new(owner)`, `Promise.async(fun, owner: owner)`): a local promise is awaited once,
  by its creator (a second await hangs).
- A listener runs in a process of its own while the connection waits for it to return or first
  await. Blocking on non-Playwright work there stalls dispatch, as it would in JS.
- A closed context (and what it owned) stays readable until the processes that created or
  closed it have exited;
  reads after that raise TargetClosedError. Tests read closed objects in the test process.
- Check-then-subscribe (`if (!cond) await waitForEvent(...)`) is one tick in JS; here dispatch
  may run in between. Subscribe before the check, or make the check part of the subscription.
- JS runs the statements after an `await` before it dispatches the next message; here the caller
  runs them in its own process, maybe after the next event. When an event the call enables reads
  what they write (`this._bindings.set(...)` before a `bindingCall`), put them in `channel_call/5`'s
  `on_reply`: it runs in the connection when the reply is dispatched (pure state, no await).
- Public entry points run inside `PlaywrightEx.Runtime.Api.call/3` (the generated facade does
  this for async methods): it names the call for error messages; it does not block dispatch.

## Tests

- North star: run no more upstream specs than the non-JS clients (Python, Java, .NET) can. Specs
  of JS-only API (api.json `only: ["js"]`, e.g. `launchServer`), of the in-process server
  (`toImpl`, `__testHook*`, heap counts) or of the test runner stay bodiless `not ported`: the
  driver's behaviour is the same under every client and upstream's to test. Port what
  exercises the client. Benchmark: playwright-python `tests/upstream_not_ported.txt` and
  playwright-java `playwright/src/test/upstream_not_ported.txt` (rules against upstream's
  `tests/registry.md`, same format as ours); a spec they run (e.g. via the driver's
  `launch-server` CLI) we run too.
- Mirror upstream spec files: one module per file, `@upstream "tests/page/page-goto.spec.ts"`
  then `use PlaywrightEx.UpstreamCase` (which tags the module with it: `mix test --only
  upstream:tests/page/page-goto.spec.ts`), test names identical to upstream.
- Keep the upstream order. A test that is not ported stays as a bodiless test (`test "should
  work"`), and its reason goes in `test/upstream_not_ported.txt` (the playwright-python/java
  mechanism): one rule per line, a selector then the reason; the selector is a registry ID
  (`CL-067`), a subsystem code (`CG`) or a spec glob without `.spec.ts` (`library/inspector/*`).
  IDs come from `test/upstream_registry.md` (upstream's `tests/registry.md`, copied from
  playwright-python; a test matches its row by `@upstream` file and name, the `describe` tells
  same-named tests apart). `PlaywrightEx.UpstreamCase` skips a rule-matched test at compile
  time (`not ported: <reason>`, over the test's own skip tags). Conditional exclusions (one
  browser, one loop variant) stay `@tag skip: if(..., do: "not ported: ...")` in the file;
  env/upstream/flaky/ci tags stay in the file too.
- `mix playwright_ex.parity` compares the names, and checks the rules as Python's
  `check_test_registry.py`: every registry test at the pin is ported (has a body), bodiless under
  an unconditional `upstream skip/fixme` tag, or ruled out; a ported test that a rule matches,
  or a rule that matches nothing at the pin, fails. Registry rows of tests newer than the pin
  are ignored; mirrored tests the registry lacks (renamed upstream) are listed, not failed. A
  spec with no test module needs all its tests ruled out (driver internals, Node-only tooling).
  It also fails on stale skips: a reason (tag or rule) that only lists API names (`not ported:
  Page.emulateMedia`, `not ported: Locator.evaluate (ElementHandle), expect`) where a cited
  `Class.member` is exported by the client or facade. Port the test then. If the member exists
  but the test still needs something missing, say so in words (`not ported:
  Page.removeAllListeners behavior option`); the check skips prose.
- North star: `mix playwright_ex.parity --north-star` lists the tests we rule out that
  playwright-python runs, and the tests it rules out that we run (informational).
- Fixtures mirror upstream's (`server`, `https_server`, `browser_type`, `browser`, `asset`, ...),
  see `PlaywrightEx.UpstreamCase`. `PlaywrightEx.TestServer` ports `tests/config/testserver`;
  assets and certs come from `PlaywrightEx.Upstream` (the pinned release, not vendored).
- Tests call the facade (`BrowserType.launch(browser_type, executable_path: path)`), with
  `{:error, e} = ...` for `.catch(e => e)` and the bang form otherwise. Options get snake_case
  keys, nested objects stay as upstream writes them, as maps with the JS keys
  (`new_context(browser, viewport: %{width: 456, height: 789}, record_video: %{dir: dir})`).
- Keep assertions verbatim (we announce `sdkLanguage: "javascript"`, as upstream). Options
  passed `as any` are rejected by the facade: assert that, with a comment.
- CI-only failure or flake under load? Reproduce in the Linux container: `scripts/linux/README.md`.
- Annotations keep their conditions: `it.skip(browserName === 'webkit')` is `@tag skip:
  if(@browser_name == "webkit", do: "upstream skip: ...")` on the ported body (an unconditional tag
  only when the condition holds in every run here: headless, out-of-process driver; parity flags
  the others). `it.fail(cond)` wraps the whole body in `expected_failure(cond, fn -> ... end)`
  (`PlaywrightEx.UpstreamCase`): where `cond` holds the test passes only if the body fails, as
  Playwright Test fails an unexpected pass; elsewhere the body runs as is. No `refute` of the
  last assertion.
- Contexts get Playwright Test's default options (`locale: "en-US"`, 1280x720 viewport, `light`
  color scheme, ...) and launches its default launch options (`tracesDir`, `artifactsDir`, ...)
  from `PlaywrightEx.UpstreamCase.setup_playwright/2`, as upstream's fixtures register them; a
  test that drops one passes it as upstream does (`launch(browser_type, artifacts_dir: nil)` for
  `{ artifactsDir: undefined }`). A driver of the test's own: `start_playwright/2`.
- Headed: `HEADED=1` is upstream's `--headed` (the `headless` fixture, `_defaultLaunchOptions`).
  Tag every test that launches headed (or that upstream skips when headless) `@tag :headed`: CI
  runs `HEADED=1 mix test --only headed` (Linux: under `xvfb-run`). Other specs' `!headless`
  annotations stay comments, as we run them headless.
- `:headed` tests are excluded on macOS (windows steal focus): `mix test --include headed`.

## Bumping the pinned version

`.github/workflows/upstream-update.yml` checks npm daily and opens a draft PR doing these steps
(`.github/prompts/upstream-update.md`); finish its checklist by hand.

1. Bump `@driver_version` (and Node if Python did) in `PlaywrightEx.Driver`, run
   `mix playwright_ex.checksums`.
2. `mix playwright_ex.gen.protocol` and `mix playwright_ex.gen.api`, commit the generated diff.
3. `git diff vA vB -- packages/playwright-core/src/client tests/page tests/library` in upstream; port the hunks.
4. `mix playwright_ex.parity` until clean, then `mix test`. New upstream client or spec files
   show up as missing, removed or since-ported ones as stale exclusions: port or mirror them, or
   update `@unported_client_files` / `test/upstream_not_ported.txt`. Refresh
   `test/upstream_registry.md` from playwright-python (or upstream's `tests/registry.md`).
